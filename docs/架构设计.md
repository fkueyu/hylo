# Hylo 系统架构设计

Hylo 是一款定义为“HTML 的 Typora”的 AI 原生可视化编辑器。本文档详细阐述了其底层的技术选型与核心模块设计。

## 核心技术栈

- **前端框架**: React 19 + TypeScript + Vite
- **底层驱动**: Tauri v2 + Rust
- **代码编辑器**: Monaco Editor (`@monaco-editor/react`)
- **AST 解析引擎**: `parse5` (纯粹的 HTML5 标准解析引擎)
- **多语言支持**: 内部极简的 i18n 机制 (中/英)

## 系统核心模块

### 1. 双向联动引擎 (SyncManager & NodeMapManager)
Hylo 的核心灵魂在于“源码”与“预览”的无缝联动：
- **`parseHTML` (ast-parser.ts)**: 利用 `parse5` 将用户输入的 HTML 实时解析为抽象语法树 (AST)，并生成节点标识（`__hylo_id__`）。
- **`NodeMapManager`**: 维护一张巨大的映射表，记录每一个 `__hylo_id__` 在 Monaco 编辑器中的精确起止行号 (SourceLocation)。
- **双向同步交互**:
  - **点击预览树节点** -> 查询 NodeMap -> 驱动 Monaco 的 `editor.revealPositionInCenter` 并施加 `deltaDecorations` 实现代码区域高亮。
  - **代码区光标移动** -> 查询 NodeMap -> 定位最内层 AST 节点 -> 通过事件总线触发预览区高亮。

### 2. 沙盒隔离渲染机制 (PreviewPanel)
为了防止用户输入的 HTML 样式或脚本污染应用外壳，右侧预览区运行于 `sandbox="allow-scripts"` 的独立 iframe，并且不授予 `allow-same-origin`：
- React 宿主只负责解析、NodeMap、结构导航与消息校验，用户 DOM 在 iframe 运行时内重建。
- 安全预览默认忽略 `<script>`、`on*` 事件属性、危险 URL 和活动嵌入文档，同时通过 CSP 阻止远程连接。
- 用户明确开启交互预览后，HTTPS 脚本仍只在无同源权限的 iframe 内执行；源码定位通过受限 `postMessage` 协议完成。

### 2.1 系统文件关联与安全边界

- **文件关联**：`tauri.conf.json` 的 `bundle.fileAssociations` 会生成 macOS 的 `CFBundleDocumentTypes`（`html`/`htm`/`xhtml` → `public.html`，`Editor` / `Default`），Finder 双击与「打开方式」由此生效。macOS 通过 `application:openURLs:`（`RunEvent::Opened`）传文件，**不是** argv；Windows/Linux 则走命令行参数。
- **冷启动竞态**：系统事件可能早于 WebView 就绪，Tauri 事件无缓冲。Rust 侧用 `PendingOpenFiles` 队列暂存，前端完成监听注册后调用 `take_pending_open_files` 一次性取走。
- **scope 与读取**：系统事件路径不在 `tauri-plugin-fs` 运行时 scope 内，因此由 Rust 命令 `read_system_open_file` 读取，并补登记 `fs` scope（保存）与 asset 协议 scope（相对路径图片）。系统事件仅接受 `.html/.htm/.xhtml` 且限制 32MB。
- **CSP 与能力**：主窗口启用 CSP；`assetProtocol.scope` 不再使用 `**`，改为按打开的文件/目录动态授权；capability 中移除了任意路径 `fs:allow-read-file` 授权。
- **退出保护**：Rust 拦截 `RunEvent::ExitRequested`，前端 `allow_app_exit` 确认后才放行，保证 Cmd+Q / Dock / 系统注销 / 更新重启都不会静默丢弃未保存修改。
- **单实例（Windows/Linux）**：`tauri-plugin-single-instance` 把第二次启动的 argv 转发给已运行实例，复用「打开方式」链路；macOS 由 LaunchServices 直接投递事件，无需该插件。
- **交互预览脚本复用**：iframe 运行时按 `src + 属性` 或 `内联内容哈希` 生成脚本 key，渲染时取新旧脚本列表的最长公共前缀，未变化的脚本保持已执行状态；前缀之后的脚本先移除再按顺序重放，保证依赖顺序（避免每次输入都重跑整页 JS / 重拉 CDN）。
- **大纲虚拟化**：`flattenOutline` 把 AST 结构树按折叠状态压平成行列表，`DocumentOutline` 依据滚动位置只渲染视口附近行，用上下占位 div 撑起总高度；键盘导航基于行索引，选中节点会自动滚动到可视区域。
- **节点标识**：`@ainx/hylo-core` 的 AST 节点 ID 采用「祖先链 + 显式 id 锚点 / 同标签序号」生成（如 `section_id_intro`、`p_2`、`text_1`）。带 `id` 的元素在任意兄弟插入下保持身份；无 id 元素在插入**不同标签**兄弟时保持身份；重复 id 自动加 `__2` 后缀。这样增量 patch、双向定位和就地编辑在常见编辑下不会因 ID 漂移而失效。
- **预览增量渲染**：宿主把 AST 序列化到 iframe 后，iframe 内按 `data-hylo-id` / `data-hylo-text-id` 复用已有 DOM 节点做 keyed patch；只有安全/交互预览模式切换时才全量重建，避免每次输入重置滚动位置、表单状态与动画。
- **CSP 注意点**：Tauri 会给 `script-src` 注入 nonce/hash，而 CSP 规范规定 nonce/hash 存在时 `'unsafe-inline'` 失效。预览 iframe 依赖内联运行时脚本，因此 `script-src` 关闭了 Tauri 的自动修改（`dangerousDisableAssetCspModification`），其余指令仍由 Tauri 注入 hash。另外父文档 CSP 的 `base-uri` 必须放行 asset 协议，否则 iframe 内的 `<base href="asset://…">` 会被拦截、相对路径图片失效。

### 3. Tauri v2 底层融合桥接
Hylo 不是一个简单的套壳 Web App，而是深度整合了系统级底层能力的 Native 应用：
- **原生应用交互**: 通过 `@tauri-apps/plugin-fs` 跨过浏览器沙盒直接对本地硬盘进行原生的 I/O 读写。
- **全局原生菜单联动**: 在 Rust 侧 (`src-tauri/src/lib.rs`) 构建基于操作系统的系统原生菜单栏，并在点击时通过跨进程事件总线 (IPC `app_handle.emit`) 向 React 发送命令（如 `save-file`、`toggle-theme`）。
- **macOS 本地化深度适配**: 通过嵌入 `Info.plist`（输入 `-Wl,-sectcreate` 链接器属性）将应用的语言声明固化到二进制文件内，确保系统原生对话框（保存/打开面板）在正式打包后能正确显示中文。

### 4. 彻底重构的右键系统 (ContextMenu)
为解决 Monaco Editor 与 Tauri/WebKit 环境下复杂的右键事件劫持冲突，Hylo 实现了一套“降维”接管的右键生态：
- 通过强制在 Monaco 内核传递 `contextmenu: false` 关闭内置劫持。
- 在全局的 `.app`、`.monaco-panel__editor` 容器上直接绑定 `onContextMenu` 拦截系统级右键事件（辅以防冒泡逻辑）。
- 所有复制、剪切、粘贴绕过了陈旧的 `document.execCommand` 限制，直接对接了现代异步的 `navigator.clipboard` 系统级剪贴板 API。
