# Hylo AI 审阅工作台深化设计

## 目标

将 Hylo 从“带实时预览的 HTML 编辑器”深化为面向 AI 内容创作者的 HTML 审阅与精调工作台。保留源码与预览双向定位这一核心，不引入账号、云端或模型 API。

## 核心场景

1. 用户从 AI 对话中复制完整 HTML，通过一个明确入口直接载入 Hylo。
2. 用户通过文档结构导航快速理解长文档，点击结构节点即可同步定位源码与预览。
3. 用户在源码、结构与预览之间移动时，始终知道当前选中的元素及其层级。
4. 用户可继续使用打开、保存、导出、历史记录和三种布局模式。

## 信息架构

- 顶部工作栏：品牌与文件状态在左；“粘贴 HTML”作为首要动作；结构开关、布局、导出和主题作为次级工具。
- 工作区：左侧为源码工作面板，右侧为预览画布；默认比例调整为 40/60，让内容创作者优先看到结果。
- 文档结构：作为源码面板内可折叠的窄侧栏，不新增全局页面或常驻弹窗。
- 选中上下文：在两个面板头之间共享同一套元素层级信息，让双向联动可被看见和理解。

## 新增能力

### 从剪贴板载入 HTML

- 读取系统剪贴板文本。
- 空文本或不含 HTML 元素的普通文本不覆盖当前文档，并给出明确错误提示。
- 当前文档有未保存修改时，复用防丢失确认流程。
- 载入成功后成为新的未命名文档，保留保存路径为空。

### 文档结构导航

- 只展示具有编辑意义的元素节点，忽略文本、注释、doctype 与隐式无源码节点。
- 标签标题优先使用 `id`，其次使用 class 的第一个名称；同时显示语义标签名。
- 点击结构节点复用现有 `handlePreviewClick`，同步定位源码和预览。
- 当前选中节点及祖先路径可见，结构面板自动展开对应分支。

### 选中元素上下文

- 从 AST 计算当前节点的祖先路径。
- 面板头显示紧凑 breadcrumb；未选中时显示“选择预览中的元素以定位源码”。
- 不引入属性编辑器或 WYSIWYG 写回，避免破坏现有 AST/source-map 边界。

## 视觉系统

- 主题：深石墨工作台 + 纸张预览画布，浅色模式保持同一层级逻辑。
- 品牌色：`#7067F0`（映射紫）、`#22C7B8`（结构青）；紫色负责选中，青色负责源码/预览联动信号。
- 中性色：`#15161A`、`#1D1F24`、`#282B31`、`#F7F8FA`、`#A8ADB8`。
- 字体：界面使用系统 UI 字体，代码使用 Monaco 配置的等宽字体；不下载远程字体，保证桌面应用离线可用。
- 标志性元素：分隔线变为“映射轨道”，选中节点时呈现短促青色信号，表达源码与预览的对应关系。
- 动效：仅保留结构展开、选中反馈和分隔线信号；支持 `prefers-reduced-motion`。

## 响应与无障碍

- 窗口宽度低于 1040px 时隐藏次要统计文字，保持主动作可用。
- 文档结构按钮、树节点、布局按钮具有可见焦点和 ARIA 状态。
- 不使用 emoji 作为主题图标，改用一致的线性 SVG。
- 明暗主题均满足主要文字与背景的可读对比。

## 验证

- 纯函数单元测试：HTML 剪贴板判断、结构树生成、节点 breadcrumb 查找。
- TypeScript 与 Vite 完整构建。
- 本地界面检查：默认/结构展开/节点选中/浅色主题/窄窗口。
